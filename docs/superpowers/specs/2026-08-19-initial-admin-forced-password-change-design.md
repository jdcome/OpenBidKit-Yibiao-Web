# GitHub Web 版首次管理员强制改密设计

> 日期：2026-08-19
>
> 状态：已实现、已验证
>
> 适用仓库：`jdcome/OpenBidKit-Yibiao-Web`
>
> 适用范围：仅全新安装；升级已有部署不得重置或强制修改现有管理员密码

## 1. 背景与目标

公开 Web 版需要降低首次部署门槛：全新安装完成数据库初始化后，管理员可使用固定账号 `admin`、固定密码 `admin` 进行第一次身份验证。由于该默认凭据是公开信息，默认密码阶段不得授予任何业务访问权限。

本次改造目标：

1. 仅全新安装创建 `admin/admin`；
2. 首次验证默认凭据后强制展示不可关闭的改密弹窗；
3. 新密码必须至少 12 位，并同时包含大写字母、小写字母、数字和特殊字符；
4. 改密完成前不能进入系统或调用任何业务接口；
5. 改密成功后直接签发正式登录令牌并进入系统；
6. 升级已有部署时不重置密码、不改变现有管理员的登录行为；
7. 重复执行 seed 不覆盖已经修改的管理员密码。

## 2. 非目标

- 不调整普通用户注册密码的现有规则；
- 不把所有管理员统一纳入周期性改密；
- 不新增找回密码、短信验证或多因素认证；
- 不重置已经部署系统中的管理员凭据；
- 不把密码、受限令牌或正式令牌写入日志、文档或 Git 仓库。

## 3. 方案选择

采用“数据库显式状态 + 短时受限改密令牌”。

不采用根据密码哈希反推默认状态的方案，因为这会把安全策略与具体密码长期耦合，无法明确区分首次初始化和后续人为重置。也不采用独立安装向导，因为它不符合 `admin/admin` 首次登录的既定交互。

## 4. 数据模型与升级兼容

在 Prisma `User` 模型增加：

```prisma
mustChangePassword Boolean @default(false)
```

状态语义：

- 全新安装创建的默认管理员：`true`；
- 已有数据库执行 `prisma db push` 后：默认补为 `false`；
- 普通注册用户：`false`；
- 初始密码修改成功后：从 `true` 原子更新为 `false`。

字段默认值必须为 `false`，这是保证已有部署升级不被强制改密的兼容边界。

## 5. 全新安装与 seed 行为

seed 先检查用户表：

1. 用户总数为 `0` 时，创建唯一默认管理员；
2. 默认账号固定为 `admin`；
3. 默认密码固定为 `admin`，只以 bcrypt 哈希形式写入数据库；
4. 默认管理员设置 `role=admin`、`status=active`、`mustChangePassword=true`；
5. 用户表已有任何记录时，不创建、更新或重置默认管理员；
6. 重复执行 seed 只继续完成其他幂等初始化，不覆盖用户凭据。

环境模板不再要求 `INITIAL_ADMIN_PASSWORD`。初始化日志只说明默认管理员是否创建或因已有用户而跳过，不打印密码或哈希。

“用户表为空”用于界定全新安装。正常 UI 不允许管理员删除自己，因此常规升级与重复部署不会重新触发默认管理员创建。

## 6. 令牌模型

系统保留现有 7 天正式 JWT，并增加 10 分钟有效的初始改密 JWT。

受限令牌至少包含：

```json
{
  "id": 1,
  "username": "admin",
  "role": "admin",
  "purpose": "initial-password-change"
}
```

安全约束：

- 现有 `verifyToken` 必须显式拒绝 `purpose=initial-password-change`；
- 受限令牌只能由初始改密接口的专用校验器接受；
- 为兼容升级前已签发的正式 JWT，没有 `purpose` 字段的旧令牌继续按正式令牌处理；
- 改密接口还必须查询数据库中的 `mustChangePassword=true`，因此字段清除后旧受限令牌立即失效；
- 令牌不写入日志；受限令牌不写入 `localStorage`。

## 7. 登录接口

现有 `POST /api/login` 保持账号密码验证、账号状态门禁和普通登录响应。

### 7.1 正常登录

对 `mustChangePassword=false` 的有效账号返回：

```json
{
  "token": "正式登录令牌",
  "user": {}
}
```

### 7.2 首次管理员验证

对 `mustChangePassword=true` 的有效管理员，不签发正式令牌，返回：

```json
{
  "password_change_required": true,
  "password_change_token": "短时受限令牌",
  "expires_in": 600
}
```

此时前端不得持久化用户、启动 SSE 或挂载业务应用。

## 8. 初始密码修改接口

新增公开挂载但内部使用专用受限令牌校验的接口：

```text
POST /api/change-initial-password
Authorization: Bearer <password_change_token>
```

请求体：

```json
{
  "newPassword": "New-Strong-Password",
  "confirmPassword": "New-Strong-Password"
}
```

服务端校验顺序：

1. 受限令牌签名、有效期和 `purpose` 正确；
2. 用户存在、状态为 `active`、角色为 `admin`；
3. 数据库中 `mustChangePassword=true`；
4. 两次密码一致；
5. 新密码至少 12 位；
6. 同时包含 ASCII 大写字母、小写字母、数字和特殊字符；
7. 新密码不得为 `admin`，不得与当前密码相同。

所有规则必须在服务端执行；前端校验仅用于即时反馈。

通过后以 bcrypt 生成新哈希，通过带 `id + mustChangePassword=true` 条件的原子更新同时写入新密码并清除强制改密状态。若条件更新数为 `0`，按已经修改或状态失效处理，防止并发重复提交和令牌重放。

成功响应返回与正常登录一致的正式令牌和用户信息。前端保存正式令牌后直接进入系统。

## 9. 前端状态与弹窗

`AuthProvider` 增加仅驻留内存的待改密状态，不把受限令牌写入浏览器持久存储。

登录流程：

1. 用户提交账号和密码；
2. 正常响应沿用现有登录路径；
3. `password_change_required=true` 时保持 `user=null`，保存内存态受限令牌；
4. `LoginPage` 打开 Radix Dialog 强制改密弹窗；
5. 弹窗不能点击遮罩关闭、不能按 Esc 关闭、没有关闭按钮；
6. 表单展示新密码、确认密码、显示/隐藏密码按钮以及四类强度条件；
7. 提交成功后持久化正式令牌和用户信息、启动 SSE、挂载业务应用；
8. 页面刷新会清除内存态并回到登录页，需要重新用默认凭据验证；
9. 受限令牌过期时清除待改密状态并提示重新登录。

前端文案全部使用中文。密码值不得写入 `localStorage`、`sessionStorage`、URL、Toast 详情或控制台。

## 10. 错误处理

- 无效或过期受限令牌：`401`，提示“改密凭证无效或已过期，请重新登录”；
- 非初始改密令牌：`403`，提示“该凭证不能用于初始密码修改”；
- 用户已停用或不存在：`401`；
- 非管理员或未处于强制改密状态：`403` 或 `409`；
- 两次密码不一致或强度不足：`400`，返回具体中文规则提示；
- 重复提交或并发状态已改变：`409`，提示“初始密码已经修改，请使用新密码登录”；
- 网络错误：前端保留当前输入，允许重试，但不持久化密码。

## 11. 测试与验证

### 11.1 seed 与升级兼容

- 空用户表创建 `admin/admin`，并设置 `mustChangePassword=true`；
- 非空用户表不创建、不修改任何管理员密码；
- seed 重复运行不覆盖改密后的哈希或状态；
- Prisma schema 校验通过；
- 现有数据库增加字段后已有用户均为 `false`。

### 11.2 服务端认证

- 默认凭据正确时只返回受限令牌；
- 默认凭据错误时返回 `401`；
- 受限令牌访问 `/api/me` 和业务接口时被拒绝；
- 11 位密码及缺少任一字符类型的密码被拒绝；
- `admin`、默认密码、当前密码被拒绝；
- 合格密码修改成功，返回正式令牌；
- 同一受限令牌不能重复使用；
- 修改后 `admin/admin` 登录失败，新密码登录成功；
- 普通用户登录、注册、审批和模块权限行为保持不变；
- 升级前已签发且没有 `purpose` 字段的正式令牌仍可使用。

### 11.3 前端

- 默认管理员验证后不渲染业务应用；
- 强制弹窗不能通过遮罩或 Esc 关闭；
- 密码规则逐项反馈正确；
- 修改成功后直接进入系统并启动正常登录生命周期；
- 刷新和令牌过期回到登录页；
- 前端生产构建通过。

## 13. 验收标准

全新空数据库执行初始化后，使用 `admin/admin` 只能进入强制改密流程；在服务端确认符合强度规则的新密码并原子清除初始化状态前，默认凭据不能获得任何业务访问能力。修改成功后直接进入系统，默认密码立即失效。已有数据库升级与重复 seed 均不得改变任何现有用户密码。
