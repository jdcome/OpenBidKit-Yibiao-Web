# Web 版模块、品牌、主题与使用文档设计

> 日期：2026-08-19
>
> 状态：已实现、已同步 GitHub、已用于 92:8088 Web 版部署验证
>
> 适用仓库：`jdcome/OpenBidKit-Yibiao-Web`

## 1. 背景

当前仓库用于发布可独立安装运行的 OpenBidKit 易标 Web 版。它既要保留原项目的 AGPL-3.0-only 授权、原作者、原仓库、LICENSE 和 NOTICE，也要清晰说明 Web 二开后的功能边界，让其他人从 GitHub 下载后能按同一套说明完成部署和使用。

本次整理围绕 6 个变化：

1. 移除资源下载模块；
2. 将“商务标”入口调整为“投标计算器”；
3. 迁移 98 系统的浅色/深色双色主题体验；
4. 将全新安装默认系统名称调整为“易标投标工具箱web版”；
5. 将 98 的使用文档沉淀到 92:8088 和代码仓库；
6. 更新 README、功能清单、架构和部署说明，使 GitHub 仓库与实际 Web 版一致。

## 2. 目标

- GitHub 仓库描述必须能让新部署者理解当前功能范围，而不是误以为仍包含资源下载模块。
- 菜单、权限、文档里的模块名称保持一致：标书生成下的原“商务标”统一展示为“投标计算器”。
- 深色模式和浅色模式作为 Web 基础体验提供，且不破坏现有业务组件结构。
- 默认品牌从服务端默认配置、前端 fallback、页面标题和导出元数据保持一致。
- 使用文档必须进入仓库，并能在全新安装后通过 seed 写入数据库。
- 开源合规入口继续保留原作者、原仓库、当前修改版源码、LICENSE、NOTICE 和 AGPL 声明。

## 3. 非目标

- 不上传生产数据、测试数据、数据库备份、密钥、日志、客户标书或上传文件。
- 不把 92:8088 的数据库内容作为仓库内容发布；仓库只保存初始化文档和源码。
- 不恢复资源下载功能。
- 不把投标计算器在本次整理中扩展为完整评分引擎；当前仍保留开发中提示。
- 不改动 80 端口旧系统。

## 4. 功能模块设计

### 4.1 资源下载模块移除

资源下载模块不再作为 Web 版默认能力提供。设计要求：

- 主菜单和子菜单不展示资源下载；
- 普通用户可授予模块白名单不包含资源下载；
- 功能介绍、部署说明和 README 不把资源下载列为当前能力；
- 旧数据或旧链接不作为本次发布的兼容目标。

### 4.2 投标计算器

原“商务标”入口保留路由和内部 id，避免破坏既有代码引用，但对用户展示调整为：

- 菜单名称：投标计算器；
- 模块简介：综合报价、技术、商务评分标准计算标书最终得分；
- 页面定位：作为未来评分计算能力入口；
- 弹窗提示：保持原“正在开发中，敬请期待。”，避免承诺尚未实现的完整计算功能。

### 4.3 标书生成模块关系

标书生成下保留 4 个入口：

1. 生成技术方案；
2. 已有方案扩写；
3. 投标计算器；
4. 响应与偏离表工作台。

这 4 个入口共同覆盖从招标文件解析、方案生成、方案扩写、响应偏离表到未来评分计算的主流程。

## 5. 品牌与主题设计

### 5.1 默认系统名称

全新安装默认系统名称为“易标投标工具箱web版”。默认值应存在于：

- 服务端系统配置默认值；
- 登录页和顶栏的前端 fallback；
- HTML title；
- 导出文档元数据；
- 测试断言。

已有部署如果数据库中已经有自定义系统名称，升级代码不强制覆盖；管理员可以在“设置 - 基本设置”中修改。

### 5.2 Logo 与开源归属

默认 Logo 和图标保留上游公开源码中的资产。管理员可以在运行时修改系统 Logo，但仓库必须继续保留：

- 原作者 `mark / yibiaoai`；
- 原始仓库 `https://github.com/FB208/OpenBidKit_Yibiao`；
- 当前修改版源码 `https://github.com/jdcome/OpenBidKit-Yibiao-Web`；
- `LICENSE`；
- `NOTICE`；
- AGPL-3.0-only 授权说明。

### 5.3 深色/浅色主题

主题由客户端 `ThemeProvider` 管理：

- 主题值：`light`、`soc-dark`；
- 本地存储键：`yibiao_ui_theme`；
- DOM 标记：`html[data-theme='soc-dark']`；
- 切换位置：登录后的应用顶栏；
- 样式实现：深色主题文件最后加载，通过作用域选择器覆盖浅色样式。

Markdown 文档和 Mermaid 图会读取当前主题，保证使用文档在深色模式下可读。

## 6. 使用文档设计

使用文档分为两份存储：

- `server/prisma/seed-docs/`：数据库 seed 的 Markdown 原稿；
- `client/public/docs/`：前端静态资源副本和图片引用路径。

数据库写入由 `server/prisma/seed-docs.ts` 完成，固定 id 包括：

- `usage-01` 至 `usage-05`：生成技术方案、已有方案扩写、使用文档知识库、标书查重、废标项检查；
- `faq`：常见问题；
- `config-01` 至 `config-04`：配置文本模型、配置生图模型、选择文件解析方式、智能体配置。

seed 策略：

- 新部署时创建文章；
- 重复执行时刷新 section、title 和 content；
- 不覆盖管理员手动调整过的 sortOrder；
- 不写入任何生产数据或客户数据。

## 7. 权限设计

权限模型保持二元角色：

- `admin`：可访问所有模块；
- `user`：默认可访问仪表盘、标书生成和设置；其他模块按授权列表控制。

普通用户可授予模块为：

- `template-settings`：格式管理；
- `knowledge-base`：知识库；
- `bid-check`：标书检查；
- `docs`：使用文档；
- `faq`：问题 FAQ。

用户管理和提示词管理为管理员专属。资源下载不在授权白名单内。

## 8. 部署与更新

全新部署的推荐顺序：

1. 准备 PostgreSQL 空库和 `.env`；
2. 安装依赖；
3. 执行 `pnpm exec prisma generate`；
4. 执行 `pnpm exec prisma db push`；
5. 执行 `pnpm run db:seed`；
6. 执行 `pnpm exec tsx prisma/seed-docs.ts`；
7. 构建前端并由 Nginx 托管 `client/dist`；
8. 使用 PM2 启动后端；
9. 使用 `admin/admin` 完成首次强制改密；
10. 验证系统名称、主题切换、使用文档、权限菜单和核心业务入口。

升级已有部署前必须备份 PostgreSQL 和运行数据目录。仓库同步不包含生产 `.env`、数据库备份、日志或上传文件。

## 9. 验收标准

- README 和功能清单能准确说明当前 Web 版功能范围；

- “投标计算器”名称、简介和开发中提示与界面一致；
- 默认系统名称在全新安装路径中为“易标投标工具箱web版”；
- 深色/浅色主题入口和实现边界写入架构说明；
- 使用文档 seed 命令写入部署说明；
- AGPL、NOTICE、原作者和原仓库归属不被删除或弱化；
- GitHub 发布范围不包含生产数据、测试数据、密钥、备份、日志或客户文件。
