# 功能设计、说明、规划

> 日期：2026-08-20
>
> 状态：已实现，本文档为面向 GitHub 发布的产品化说明口径
>
> 适用仓库：`jdcome/OpenBidKit-Yibiao-Web`

## 1. 设计背景

OpenBidKit 易标 Web 版面向浏览器访问、多用户协作和企业内网部署，本项目更适合于服务类项目招投标项目，工程类、产品类等其他类型招投标项目未进行调优。

它需要让首次安装者在不依赖桌面壳和本地开发环境的情况下，完成数据库初始化、管理员首次登录、模型配置、使用文档查看和日常标书编制。

公开文档应当服务于部署者、管理员和二次开发者，而不是记录某一次内部迁移或某台服务器的改造过程。因此 README、功能清单、架构说明和部署指南只描述当前 Web 版能力、运行边界、安全建议和 AGPL 合规要求。

## 2. 设计目标

- 可以使用AI编程工具VibeCoding属于你独有的标书编制系统；
- 模块说明与 Web 菜单、权限白名单、路由和内置使用文档保持一致；
- 默认系统名称、Logo 展示、源码入口、原作者归属、LICENSE、NOTICE 和 AGPL 声明保持清晰可见；
- 深色/浅色主题成为 Web 基础体验，主题切换不破坏业务页面结构；
- 内置使用文档可随源码发布，并能在全新安装后通过 seed 写入数据库；
- 部署说明同时覆盖本地内网部署、通用大模型互通和云平台虚拟机安全建议；
- 文档中不写入生产数据、测试数据、服务器地址、密钥、备份、日志或客户资料。

## 3. 文档口径

公开文档采用“产品说明 + 部署说明 + 安全边界”的口径：

- README：说明项目定位、核心功能、环境要求、本地启动、部署建议和开源义务；
- 功能清单：说明 Web 版当前模块、权限关系和运行数据边界；
- 架构文档：说明 client/server/PostgreSQL/Nginx/PM2、鉴权、权限、主题、AI 和数据边界；
- 部署指南：说明 Linux 部署步骤、硬件建议、模型互通、首次强制改密和云上安全建议；
- 设计说明：说明模块、品牌、主题、文档和部署策略背后的设计原则。

这些文档不作为内部变更日志使用，不描述历史入口名称、历史服务器迁移路径或临时验证环境。

## 4. Web 模块设计

### 4.1 工作台与项目

仪表盘作为登录后的统一入口，展示项目统计、最近项目和资质到期提醒。项目数据按项目隔离，涉及项目作用域的接口必须由服务端校验归属。

### 4.2 标书生成

标书生成保留四个入口：

1. 生成技术方案：上传招标文件，解析结构化内容，按步骤生成技术方案并导出 Word；
2. 已有方案扩写：上传已有方案，在保留真实可落地内容的前提下扩充表达和章节厚度；
3. 投标计算器：汇总综合报价、技术评分和商务评分规则，辅助计算标书最终得分；（待开发中）
4. 响应与偏离表工作台：复用招标原文和分析结果，生成技术响应与偏离表，人工填写响应内容。

### 4.3 格式管理

格式管理负责导出模板、Word 排版、标题层级、编号规则和共享模板。管理员可维护共享模板，普通用户按权限使用。

### 4.4 知识库与资产库

知识库用于集中管理可复用资料：

- 方案模板库：历史方案、服务方案、项目案例和标准响应材料；
- 工具模板库：工具截图、软著、采购证明等工具类资产；
- 公司资质库：公司证书、认证材料和到期提醒；
- 人员资质库：人员证书、认证材料和到期提醒。

知识库的设计重点是可检索、可复用、可维护，不替代人工判断资料是否适合某个投标项目,后续开发计划与商务标生成和投标计算器形成关联，自动拉取本库内的资料。

### 4.5 标书检查

标书检查提供查重、废标项检查和响应完整性检查。AI 检查结果只作为辅助，提交标书前仍需人工确认。

### 4.6 使用文档与 FAQ

使用文档提供系统内置教程、配置说明和常见问题。

FAQ 支持用户提交问题和图片附件，管理员回复、更新状态，并形成可复用的常见问题记录。（可通过此功能采集使用者的反馈，并针对行业持续进行提示词、功能项优化）

### 4.7 管理模块

管理模块包括：

- 用户管理：注册审批、启停账号、管理员/普通用户角色、模块权限；
- 
- 提示词管理：维护招标解析、废标检查、技术方案等平台提示词；（主要VibeCoding工程，可针对某个类型招投标项目持续快速迭代和优化，目前版本只针对服务类项目进行过提示词优化）
- 
- 基本设置：系统名称、Logo、开源归属和基础展示配置。

## 5. 权限设计

权限模型保持二元角色：

- `admin`：可访问所有模块，负责用户管理、提示词管理和系统设置；
- `user`：默认可访问仪表盘、标书生成和设置；其他模块按授权列表控制。

普通用户可授予模块：

- `template-settings`：格式管理；
- `knowledge-base`：知识库；
- `bid-check`：标书检查；
- `docs`：使用文档；
- `faq`：问题 FAQ。

权限约束必须同时存在于前端菜单/路由和后端模块门禁。前端隐藏菜单不能替代服务端鉴权。

## 6. 品牌设计

### 6.1 默认系统名称

全新安装默认系统名称为“易标投标工具箱web版”。

- 服务端系统配置默认值；
- 登录页和顶栏 fallback；
- HTML title；
- 导出文档元数据；
- 测试断言。

已有部署如果数据库中已经保存自定义系统名称，升级代码不应强制覆盖。管理员可在“设置 - 基本设置”中修改系统名称和系统 Logo，可同步需改所有系统名称和logo。

### 6.2 Logo、源码入口与开源归属

默认 Logo 和图标保留公开源码中的资产。管理员可以在运行时修改系统 Logo，但仓库和界面必须继续保留：

- 原作者 `mark / yibiaoai`；
- 原始仓库 `https://github.com/FB208/OpenBidKit_Yibiao`；
- 当前修改版源码 `https://github.com/jdcome/OpenBidKit-Yibiao-Web`；
- `LICENSE`；
- `NOTICE`；
- AGPL-3.0-only 授权说明。

登录页和应用内开源说明组件用于展示这些归属信息。部署方可通过 `VITE_SOURCE_REPOSITORY_URL` 指向正在运行版本对应的源码仓库。

## 7. 主题设计

主题由客户端 `ThemeProvider` 管理：

- 主题值：`light`、`soc-dark`；
- 本地存储键：`yibiao_ui_theme`；
- DOM 标记：`html[data-theme='soc-dark']`；
- 切换位置：登录后的应用顶栏；
- 样式实现：深色主题文件最后加载，通过作用域选择器覆盖浅色样式。

浅色模式适合日常办公和文档阅读；深色模式适合长时间查看仪表盘、后台任务、文档解析结果和复杂表格。Markdown 文档和 Mermaid 预览需要读取当前主题，保证使用文档在两种模式下都可读。

## 8. 使用文档设计

使用文档采用“静态原稿 + 数据库文章”的双层设计：

- `server/prisma/seed-docs/`：数据库 seed 的 Markdown 原稿；
- `client/public/docs/`：前端静态文档副本和图片资源；
- `server/prisma/seed-docs.ts`：将 Markdown 写入 `docs_articles`。

固定文章包括：

- `usage-01` 至 `usage-08`：生成技术方案、已有方案扩写、知识库使用教程、标书查重、废标项检查、问题 FAQ 使用教程、用户管理使用教程、提示词管理使用教程；
- `faq`：常见问题；
- `config-01` 至 `config-04`：配置文本模型、配置生图模型、选择文件解析方式、智能体配置。

seed 策略：

- 全新部署时创建文章；
- 重复执行时刷新 section、title 和 content；
- 不覆盖管理员手动调整过的 sortOrder；
- 不写入生产数据、测试数据、客户文件或运行日志。

教程文档应尽量使用截图标注、编号步骤、注意事项和安全提醒，降低首次部署后的学习成本。

## 9. 环境与容量设计

推荐硬件按“同时在线协作人数、上传文件体积、文档解析并发、AI 任务并发”共同决定：

| 使用规模 | CPU | 运行内存 | 存储空间 | 适用场景 |
| --- | --- | --- | --- | --- |
| 单人试用/功能验证 | 2 核 | 4 GB | 40 GB SSD | 验证流程、少量项目、低并发文档解析 |
| 约 5 人共同协作 | 4 核 | 8 GB | 80 GB SSD 起 | 小团队日常编制，建议 PostgreSQL、上传目录和备份目录分开规划 |
| 约 10 人共同协作 | 8 核 | 16 GB | 160 GB SSD 起 | 多项目并行、更多文档解析和后台 AI 任务，建议预留独立备份空间 |

存储空间需要考虑数据库、上传文件、知识库资料、导出结果、日志和备份。长期运行时，备份空间不应只计算在业务盘内。

## 10. 部署与大模型互通设计

### 10.1 本地部署优先

建议优先部署在企业本地服务器、内网虚拟机或受控私有云中。主要原因：

- 招标文件、客户资料、资质证书和导出结果优先保存在自己的服务器；
- 数据库、上传目录、日志和备份策略可由企业自行控制；
- 可以通过防火墙、VPN、堡垒机和内网域名限制访问范围；
- 与本地 LibreOffice、内网文件服务器、企业代理和私有模型服务集成更方便。

### 10.2 通用大模型互通

系统通过服务端配置连接文本模型、生图模型和 Agent 运行时。管理员配置服务商、API Key、模型名称和 Base URL 后，服务端负责发起模型请求，浏览器端不保存模型密钥。

支持的互通方式包括：

- 公网通用大模型：快速启用，但需要确认项目资料是否允许出网；
- 企业统一模型网关：通过内网或受控出口访问 OpenAI-compatible 网关，便于审计、限流和密钥轮换；
- 本地或私有化模型服务：数据流转范围更可控，但需要自行保障模型质量、上下文长度和并发性能。

### 10.3 云平台虚拟机安全

部署在云平台虚拟机时，应至少满足：

- 只开放 HTTPS 入口，不直接暴露 PostgreSQL、PM2 后端端口或服务器管理端口；
- 管理入口优先走 VPN、堡垒机、零信任访问或固定来源 IP 安全组；
- 配置可信 TLS 证书、强随机 `JWT_SECRET`、独立数据库账号和最小权限；
- 首次上线前完成 `admin/admin` 强制改密；
- `.env`、数据库备份、上传文件、导出文件和日志不进入 Git 仓库；
- 定期备份 PostgreSQL 和上传目录，并测试恢复流程；
- 接入公网大模型时通过固定出口、代理审计和密钥轮换控制风险。


## 11. 下一步开发计划

- 1、计划内置web llm对话窗口，可针对目录结构、正文进行明确性改写。
- 2、多人协助可能会触发模型输入限制，目前未进行多用户高并发测试，计划增加多模型同时接入，弹性赋予不同用户调用不同模型能力，避免同一模型下生成的同项目技术文件过于类似的情况出现。
- 3、计划增设强规则弱模型技术方案生成管道，针对固定类型项目招标文件，优先规则匹配知识库方案模版内容，约束模型温度。
- 4、计划增加归档备份功能，将历史项目过程文档、数据通过定期、增量备份功能备份至独立存储空间。
- 5、优化测试投标计算器功能，可将通过公开渠道采集竞品公司资质、人员资质等并同步录入知识库，并针对同一项目，测算出竞品公司冲标可能性以及预期冲标价格（适用于综合评分法）
